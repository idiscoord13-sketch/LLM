# ایده‌ی ۱ — Edit-Signal Preference Mining `[فرضیه]`

**فرضیه:** ویرایش کاربر روی پاسخ مدل تمیزترین سیگنال ترجیح است: (ویرایش‌شده = chosen، اصلی = rejected).
**پیاده‌سازی:** `src/myllm/flywheel/build_dataset.py::edit_pair` — فقط اگر فاصله‌ی ویرایش نرمال‌شده d در `[low, high]` باشد
(خیلی کم = تایپو/نویز؛ خیلی زیاد = بازنویسی با نیت دیگر)؛ وزن = `clip(d/saturation, w_min, 1)` → `WeightedSamplerMixin`.

**آزمایش:** baseline = DPO روی داده‌ی عمومی؛ متریک = win-rate روی golden؛ ablation = (۱) بدون وزن، (۲) بدون باند پایین،
(۳) `loss_type: [sigmoid, sft]` در برابر DPO خالص.

**ادبیات (جست‌وجوی نوامبر ۲۰۲۶):**
- یادگیری از ویرایش با DPO/SFT/پاداش در یک مقاله‌ی NeurIPS 2025 بررسی شده (arXiv 2601.19055 — از طریق خلاصه دیدم، خودت تأیید کن)؛
  PRELUDE (arXiv 2404.15269) از ویرایش‌ها ترجیح نهفته را برای prompt یاد می‌گیرد.
- DPO-Positive (arXiv 2402.13228) نشان داد DPO روی جفت‌هایی با **فاصله‌ی ویرایش کم** می‌تواند دقت را خراب کند → دلیل مستقیم باند پایین
  ما و پیشنهاد اضافه‌کردن جمله‌ی SFT.
- **نتیجه:** ایده‌ی پایه جدید نیست؛ سهم ما = باند + وزن‌دهی + اجرا در flywheel فارسی و سنجش دقیق.
